# 本地中文任务界面

本界面随 v0.4.0 提供，是 harness 的本地中文浏览器前端。它通过 `HarnessClient` 调用与 MCP、CLI 相同的业务核心，不直接读写工作区数据库。界面能做的事情：

- 检查输入、查看计划、调低预算，然后提交和启动处理任务；
- 跟踪任务状态和事件，暂停、恢复、取消或核对任务；
- 查看验收结果、曲线、指标对比和产物内容；
- 在任务等待人工审核时，勾选证据、生成批准命令，并在操作者批准后提交。

任务执行当前仅支持 Windows 和固定 `paramaterial_tensile.v1`，不提供训练、Abaqus、GPU、远程执行、模型服务或检查点续算。工作区初始化和人工批准是操作者操作，只能在终端里执行。

## 启动

先按 [README](../README.md#安装)取得对应版本源码并完成安装，再安装案例依赖。以下命令在仓库根目录的 Windows PowerShell 中运行；界面本身不需要 MCP 依赖。

```powershell
.\.venv\Scripts\python.exe -m pip install -r examples/paramaterial_tensile/requirements.txt
```

1. 操作者初始化一个尚不存在的工作区目录：

   ```powershell
   .\.venv\Scripts\python.exe -m experiment_to_cpfe.cli harness init --workspace runs/harness-ui-demo --case-dir examples/paramaterial_tensile
   ```

2. 用**工作区登记的同一个 Python 环境**启动界面：

   ```powershell
   .\.venv\Scripts\python.exe -m experiment_to_cpfe_harness_ui --workspace runs/harness-ui-demo
   ```

   安装 v0.4.0 后，也可以直接运行 `.\.venv\Scripts\pipeline-harness-ui.exe --workspace runs/harness-ui-demo`，效果相同。已初始化的工作区再次使用时只执行启动命令，不重新初始化；另一次演示可用 `runs/harness-ui-demo-002`。

   启动后终端会打印一个带令牌的地址，并自动打开浏览器。参数：

   | 参数 | 说明 |
   | --- | --- |
   | `--workspace` | 已初始化工作区的路径，必填 |
   | `--port` | 监听端口，默认随机 |
   | `--no-browser` | 不自动打开浏览器 |

   如果当前解释器与工作区登记的不一致，界面会拒绝启动并说明原因；如果工作区还没有初始化，会打印初始化命令。

## 访问控制

- 服务只监听 `127.0.0.1`，每次启动生成新的随机令牌，地址里 `#token=` 之后的部分就是令牌。页面将令牌保存在当前标签页的 `sessionStorage`；缺少令牌或服务重启后，从终端复制最新完整地址重新打开。
- 业务 API 检查令牌、`Host`、`Origin` 和浏览器来源标记，工具 POST 请求只接受 JSON。HTTP 适配层开放核心登记的 17 个工具，包含前端未调用的 `inputs.register`；操作者 `init` 和 `approve` 不在工具列表中。
- 产物读取使用已登记的 `artifact_id`，不接受任意文件路径。界面会显示工作区路径、解释器路径和产物相对路径；受控文件视图也可能包含原文件记录的本机路径。
- 这不是操作系统级隔离：同一个 Windows 账户下的其他进程仍然可以直接访问工作区。

## 使用流程

1. **新建任务**：当前工作流固定为 Paramaterial 三试样，界面先检查输入，再生成计划。预算可以用滑块调低，不能超过工作区上限；处理和验收参数由工作流锁定，只在“固定参数”里只读显示。
2. **提交和启动**：同一幂等键和完全相同的请求返回原结果。同键不同请求会被拒绝。默认未勾选“独立重复计算”时，只有输入、代码、环境、预算、审核要求、协议和授权策略等冻结内容完全相同，才会返回已有任务。明确勾选 `replicate` 可创建独立重复任务。提交成功只表示排队，计算和验收状态需继续查看。
3. **跟踪**：页面可见时以 1.5 秒为轮询间隔刷新状态和事件，请求耗时会增加实际间隔；后台标签页暂停查询。刷新页面或关闭标签页不影响任务。
4. **结果**：“结果”页显示工程、数据、数值和协议各层状态，3 条应力应变曲线，Rp0.2、UTS 和弹性模量的对比；“产物”页按尝试分组列出所有登记文件，CSV、JSON、文本和 HDF5 可以分页查看。PNG 和 PDF 第一版不在浏览器中预览。
5. **人工审核**：任务进入“等待人工审核”后，在概览页勾选证据，复制生成的批准命令，由操作者在终端执行；批准后把批准编号填回界面并提交。

验收结果中的科学结论状态始终是“未建立”：通过验收表示固定案例的工程、数据、数值和协议检查满足要求，不代表材料标定、预测精度或科学泛化成立。

## 服务退出时的任务

界面服务和计算任务是不同进程。关闭终端窗口或按 Ctrl+C 会停止界面服务；计算任务能否继续运行取决于启动方式和宿主的进程管理，不能据此保证它在后台继续。界面服务退出时的各种场景尚未完成实测，请保持服务窗口打开，直到任务结束。

若 worker 消失，重新启动界面后的状态查询会结合已记录状态与进程观察，提示需要 `task.reconcile`；此时原执行状态可能仍显示“计算中”等旧值。先在任务页点“核对”，以核对后的状态决定是否重试。查询和重新打开界面不会自动重复计算；允许重试时创建新 attempt，保留旧记录。

## 常见问题

| 现象 | 原因和处理 |
| --- | --- |
| 页面显示“访问令牌无效” | 服务已重启，旧令牌失效；从终端复制最新打印的完整地址重新打开 |
| 某个操作按钮不见了 | 按钮下方的灰色列表会写明当前不能执行的操作和原因，例如状态不允许或预算已用完 |
| 冻结任务时返回 `PLAN_STALE` | 界面清除旧计划并重新预检；检查通过后再生成计划。已有任务出现 `INPUT_CHANGED`、`ENVIRONMENT_CHANGED` 或 `POLICY_CHANGED` 时，应保留旧任务并新建任务，不能修改旧收据绕过身份检查 |
| 显示“证据完整性校验失败” | 产物文件与封存记录不一致，界面不显示任何结论；检查工作区是否被手动改动，然后“重新验收”或新建任务，原文件不会被删除 |

HTTP、静态资源和打包检查不等于真实浏览器流程全部通过。版本验证范围见 [v0.4.0 发布验证记录](verification/2026-10-13-harness-release.md)。
